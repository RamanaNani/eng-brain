Quick start

Two lines in Claude Code. No clone, no build step.

/plugin marketplace add RamanaNani/eng-brain
/plugin install eng-brain@eng-brain

Then drive a feature through the pipeline:

/sdlc build offline sync for the notes editor

That runs the pipeline. To give it memory, add a brain — one command, no account:

bun add github:garrytan/gbrain && gbrain init --pglite
It works without a brain. You lose the memory, not the pipeline. Add one whenever you want decisions to carry forward.

Why this exists

Agent pipelines usually fail in one of two ways. Either every stage is a fresh start — the agent re-derives the architecture it settled last week — or the stages exist but nothing enforces them, so “run the tests” quietly becomes “say the tests passed.”

Gates are code, not prose. A stage cannot be marked complete out of order, because state.py returns exit 2 and refuses. Tests cannot be declared green without runner output, because gate.py parses that output itself and treats 3 failed, 5 passed as red.

That distinction is the whole design. Prose instructions to a model are advisory — they compete with everything else in context, and they lose under time pressure. A non-zero exit code does not lose that argument.

Decisions persist. Each stage reads the brain before deciding and writes back after, so architecture becomes a queryable graph of decisions and the ADRs that settled them — rather than a directory of markdown nobody opens again.

The ladder

/sdlc is the spine. It holds state, decides which stage runs next, and stops at the first failing gate. Stage skills work standalone, but invoked directly they cannot tell they are being run out of order — which is the problem the spine exists to fix.

Optional stages must still be recorded as skipped, with a reason. “Not applicable” is a decision, and decisions are what this system exists to keep.

Ask where anything stands:

offline-sync  ·  slice → fleet
✓ story  ✓ arch  – contract (single repo)  ✓ slice  · fleet  · before-pr  · pr  · canary

State lives in the target repo at docs/arch/<feature>/STATE.json, so a feature’s position travels with its branch and survives a lost session.

The two rules

Everything else is negotiable. These are not — and both are mechanised rather than trusted, because they are the rules most likely to be rationalised away in the moment.

Never merge

/pr opens pull requests and stops. A human accepts. No --auto-merge, no “the gate passed so I merged it.”

Never claim a green suite

…without runner output. gate.py reads pytest, jest, cargo, mocha, node --test, go test, TAP and unittest. A missing file is NOT RUN, and that is a failure.

Staying current

A SessionStart hook keeps installs from silently rotting, and behaves differently by install mode because the risk profiles differ.

clone

Detects drift between repo and ~/.claude/skills/, then re-installs automatically. The projection is derived data — rebuilding it is safe and idempotent.

plugin

Notifies only, at most once a day, when a newer version ships. Fetching code from the network is not a hook’s call to make unasked.

It is silent when there is nothing to say. A hook that speaks every session gets ignored, and then it isn’t a hook — it’s noise.
